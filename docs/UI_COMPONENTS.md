# Penggunaan komponen UI

Ikuti [sistem desain](DESIGN_SYSTEM.md) untuk token dan perilaku. Token berada di `app/tokens.css`. Gunakan CSS Modules untuk aturan lokal dan pertahankan breakpoint 48, 64, serta 90 rem sesuai kebutuhan komponen.

- `Button` untuk tindakan, dengan `type="submit"` pada form dan varian `secondary` untuk tindakan pendamping. Gunakan tautan untuk navigasi. `Input` menghubungkan label, hint, dan error serta menerima atribut native. Pakai nama field yang cocok dengan skema engine.
- `CalculatorForm` membungkus field dan submit. Berikan `invalidFields` dalam urutan visual dengan ID yang sama seperti pada input. Komponen mengumumkan ringkasan dan memfokuskan field invalid pertama setelah render. Pertahankan data input ketika hasil dibersihkan. Gunakan `ResultPanel` untuk nilai utama, rincian, asumsi, serta instruksi kosong atau invalid.
- `Directory` menampilkan kartu dan pemuatan bertahap. Proyeksikan alat terbit dengan `directoryEntry` di server. `DirectorySearch` mengelola kueri dan mengumumkan jumlah hasil. Bagikan `Breadcrumb` dan `CalculatorPage` untuk halaman kalkulator baru.
- Form kalkulator memanggil engine yang murni, lalu memformat hasil dengan locale Indonesia. Pisahkan metode dan contoh ke komponen server. HPP berjalan sinkron. Tambahkan status menunggu hanya jika kalkulator baru melakukan pekerjaan asinkron.

Aplikasi menampilkan alat terbit dan hub Bisnis dari registry. Preview Phase A memakai fixture untuk menguji kepadatan, state menunggu, dan layout masa depan. Beranda memakai judul H1 dan deskripsi yang sudah ada untuk menjaga intent SEO. Pilihan awal mengikuti urutan registry sampai ada kurasi editorial.

Untuk daftar bahan dan arus kas, gunakan fieldset dengan legend bernomor dan ID baris yang stabil. Nama field memakai jalur array untuk validasi, seperti `ingredients.0.package`. Tombol tambah memfokuskan kolom pertama baris baru. Tombol hapus memindahkan fokus ke baris terdekat. Setiap perubahan daftar membersihkan hasil lama. Batasi daftar sesuai skema dan tampilkan batasnya. `CategoryPage` membagikan layout hub yang mengambil alat terbit dari kategori registry.

`StructuredForm` membagikan input, select, payload, validasi, serta pola baris dinamis untuk beberapa batch. Form keuangan memakainya tanpa menduplikasi pola input. `LoanSchedule` menerima jadwal rupiah nonkosong yang sudah direkonsiliasi oleh engine, total pembayaran, dan total bunga. Disclosure native dapat dibuka dengan keyboard; tabel memakai caption, header kolom/baris, serta footer total. Region tabel dapat difokuskan dan digeser pada layar sempit tanpa menambah lebar halaman. Hapus jadwal lama bersama hasil saat input berubah. Komponen tidak menghitung ulang bunga dari angka tampilan.

`rowConfig` opsional pada StructuredForm menetapkan nama baris, legend, indeks awal, dan batas. NPV memulai Tahun 0 dengan maksimal 101 baris; pembelian saham memakai Transaksi 1 dan maksimal 100 baris. Tanpa konfigurasi, perilaku bahan/periode batch sebelumnya tetap sama. Nama field tetap indeks array untuk error, sementara key/ID baris tetap stabil ketika baris dihapus. `CashFlowBreakdown` memakai tabel keuangan bersama dan menandai bahwa PV baris tampilan tidak dipakai menjumlah total NPV.

Field `date` pada StructuredForm memakai input tanggal native dengan validasi kalender date-only di engine. ScenarioSchedule memisahkan cicilan biasa, tambahan pokok, penalti dan total kas; RefinanceComparison menampilkan bulan 0 serta kumulatif kas hingga kedua tenor selesai. Seluruh tabel memakai disclosure, caption, header dan region fokus bergulir dari CSS Modules tabel pinjaman yang ada.

CreatorForm memilih empat modul mandiri melalui Select native dengan label dan aria-controls. Pergantian modul me-remount form sehingga input/hasil lama dibersihkan; pilihan tetap mempertahankan fokus. CreatorComparison menampilkan akun A/B dan selisih dari hasil rasional engine melalui tabel caption/header/region fokus bergulir yang memakai CSS Modules tabel keuangan bersama.

rowConfig.min opsional menetapkan jumlah awal/minimum baris. Nilai default 1 mempertahankan semua form lama; kemasan dan orang mulai minimal2. ID/key baris dan fokus tambah/hapus tetap stabil. EverydayTables memakai gaya tabel bersama untuk rincian faktor diskon, normalisasi harga kemasan dan rekonsiliasi subtotal/biaya/tagihan; tidak menghitung ulang dari tampilan.

Field time pada StructuredForm memakai input waktu native HH:mm tanpa detik. Kalender memakai input date dan engine Gregorian date-only, tanpa zona waktu atau default tanggal sistem. Daftar libur opsional memakai rowConfig.min=0; menghapus baris terakhir mengembalikan fokus ke tombol tambah. HolidayBreakdown menerima tanggal unik yang sudah diklasifikasikan engine, dengan caption/header dan scroll region berfokus dari CSS Module tabel bersama. Pengubahan tanggal, pola mingguan, aturan akhir shift atau baris libur selalu membersihkan hasil lama.

visibleWhen opsional pada field baris menampilkan kolom hanya jika pilihan field lain pada baris tersebut cocok. StructuredForm menyimpan pilihan menurut ID stabil, memfilter kontrol/payload/error sesuai kolom aktif, dan melepas input tidak aktif sehingga nilainya tidak terbawa saat dipilih kembali. Kolom bersama tetap mempertahankan nilai dan ID. Tanpa visibleWhen, seluruh perilaku form sebelumnya tetap. Blok air memilih batas kumulatif atau tanpa batas; beton memilih balok atau silinder. MaterialsBreakdown memakai tabel caption/header/footer/scroll region bersama; biaya blok air ditampilkan eksak hingga10desimal, sedangkan volume beton empat desimal dengan catatan total tidak menjumlah baris tampilan. CSS Module metodologi material membungkus konstanta π panjang agar tidak meluaskan halaman320px.
